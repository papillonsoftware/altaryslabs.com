# OPS-001 - Remove the duplicate Cloudflare Pages project

**Type** CHR | **Status** OPEN, not started | **Branch to create** `chore/ops-projet-pages`
**Base** `refonte-multipages`

**Decisions** D046 and D047 in `docs/DECISIONS.md`.

This item touches **no file in the repository**. It is dashboard and API work on
the Cloudflare account, plus this tracking document. It can run at any time and
collides with nothing.

## The situation

Two Cloudflare Pages projects are connected to the same GitHub repository:

| Project | Production branch | State on every PR |
|---|---|---|
| `altaryslabs-com` | `main` | **fails**, permanently |
| `altaryslabscom` | `refonte-multipages` | passes |

`altaryslabs-com` fails because `main` still carries the legacy one-page site,
which has no Astro build. The failure is expected, but it posts a red check on
every pull request, and a check that is always red teaches everyone to ignore
checks. It has been red on PR #12 through PR #17.

Neither project serves the live site today: `altaryslabs.com` is still served by
GitHub Pages through the `CNAME` file on `main`.

## Decision

Delete `altaryslabs-com`. Keep `altaryslabscom`, which is the one that builds
green and whose preview URL was used to validate every page of the rebuild.

The alternative, keeping the hyphenated name because it reads closer to the
domain and repointing it at `refonte-multipages`, was rejected: the `.pages.dev`
subdomain is not customer-facing, and keeping the project that already works
carries less risk than repairing the one that never has.

## Before deleting, verify on the doomed project

Deleting a Pages project is **irreversible** and releases its name. Check all of
the following on `altaryslabs-com` and record the answers in this document
before pressing delete:

1. **Custom domains.** If any is attached, deleting could break resolution even
   though the project's builds fail: an older successful deployment may still be
   serving. Expected answer: none.
2. **Bindings.** D1, KV, R2. The contact form work will need a D1 binding; if it
   was created against the wrong project, deleting it loses the database
   association, and possibly the database.
3. **Environment variables and secrets.** Turnstile keys, the Resend API key.
   Same reasoning: if they were set on the doomed project, they must be
   recreated on the survivor before deletion, not after.
4. **Access policies or Web Analytics** attached to the project.

If any of these is non-empty, stop and report to the founder rather than
migrating them unilaterally.

## The switch to `main`, and its order

The founder's proposal was to repoint `altaryslabscom` at `main` **before**
merging the rebuild. **Do the opposite.** `main` still carries the legacy site
and no Astro build, so repointing first would make the surviving project's
production build fail immediately, on the very project the custom domains are
about to be attached to.

Correct order:

1. Delete `altaryslabs-com`, once the checks above are clear.
2. Merge `refonte-multipages` into `main`. This is a separate founder decision
   and is not part of this item.
3. Verify that `main` now builds green on `altaryslabscom`, as a preview
   deployment.
4. **Then** change the production branch of `altaryslabscom` to `main`.
5. Attach the custom domains in Pages.
6. Remove the GitHub Pages records from the DNS zone: the A records to
   185.199.108-111.153, or the CNAME to `papillonsoftware.github.io`.
7. Disable GitHub Pages in the repository.

Steps 2 to 7 belong to the DNS cutover, which is its own item and its own
founder decision. **Only step 1 belongs to OPS-001.** It is listed here so the
session doing the cutover does not have to rediscover the ordering constraint.

## Acceptance criteria

1. The four verification points above are answered in writing in this document.
2. `altaryslabs-com` no longer exists, and a pull request opened afterwards
   shows a single Cloudflare check, green.
3. No custom domain, binding or secret was lost. If any existed, it was
   recreated on `altaryslabscom` first and verified.
4. `CLAUDE.md` and the deployment notes name a single Pages project.

## Out of scope

The merge into `main`, the DNS cutover, the custom domains, and anything to do
with the contact form's D1 database.
