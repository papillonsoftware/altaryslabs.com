# OPS-002 - DNS cutover to the rebuilt site

**Type** CHR | **Status** OPEN, not started | **Branch** none for most of it
**Base** `refonte-multipages`

This is the last item. It is a **founder decision taken once, deliberately**, and
it is the only moment in the whole rebuild that can break the live site.

## Why it is dangerous

`main` still serves `altaryslabs.com` through GitHub Pages, driven by the `CNAME`
file. **The rebuild deletes `CNAME`.** Merging into `main` therefore stops the
GitHub Pages site the moment it lands. Everything below exists to make that
interval as short as possible and to make sure the replacement is already
verified when it happens.

## Preconditions

- Every page final, including Contact. `PageScaffold.astro` gone.
- The whole site validated on the `altaryslabscom` preview URL, in both
  languages, at 360, 768 and 1440 px.
- `bin/contrast_sweep` clean.
- The contact form working end to end on the preview, if `FORM-001` has landed.

## The order, and why it is this order

1. **Merge `refonte-multipages` into `main`.** Founder decision.
2. **Verify that `main` builds green** on `altaryslabscom`, as a preview
   deployment. `main` has never carried an Astro build before this point.
3. **Only then, change the production branch** of `altaryslabscom` to `main`.
   Doing this before step 1 would make the surviving project's production build
   fail immediately, on the very project the domains are about to be attached
   to. See D047.
4. **Attach the custom domains** in Pages: the apex and `www` as configured.
5. **Remove the GitHub Pages records** from the DNS zone: the A records to
   185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153, or the
   CNAME to `papillonsoftware.github.io`.
6. **Disable GitHub Pages** in the repository settings.

## After the cutover

- Check the apex and `www` resolve to Pages, in both languages, and that
  `hreflang`, the sitemap and the Open Graph images serve from the live domain.
- Update `CLAUDE.md`: `main` no longer serves a legacy site, and the branching
  section describing that constraint becomes historical.
- Flip PCS availability to "Disponible" when the product launches. It lives in a
  single dictionary constant, `availability.pcs`, so it is one line (D018).

## Acceptance criteria

1. `altaryslabs.com` serves the rebuilt site over HTTPS, both languages.
2. No GitHub Pages record remains in the DNS zone, and GitHub Pages is disabled.
3. A pull request opened afterwards shows a single green Cloudflare check.
4. `CLAUDE.md` no longer claims that `main` serves a legacy site.

## Never do

Create a Direct Upload Pages project. It cannot be converted into a Git-connected
project.
