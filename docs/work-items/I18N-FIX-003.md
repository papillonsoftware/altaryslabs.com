## Scope, quoted rather than summarised

`docs/AI_Development_Workflow.md`, section "Follow-up items born from a review",
requires the reviewer's own defining sentences **verbatim** and the severity
**that reviewer assigned**. Both follow, in the reviewer's French.

> - [ ] **[IMPORTANT]** `src/components/LangSwitcher.astro:25`,
>   `src/components/Header.astro:60` et `src/i18n/config.ts:20` - Trois
>   `aria-label` des pages anglaises portent la typographie francaise, sur
>   **toutes** les pages `/en/` du site : `aria-label="Change language : Francais"`,
>   `aria-label="Products : Open menu"` et `aria-label="Services : Open menu"`,
>   releves sur `dist/en/index.html`, `dist/en/about/index.html` et
>   `dist/en/contact/index.html`. L'anglais ne met pas d'espace avant un
>   deux-points; le francais si, et le cote francais est correct
>   ("Produits : Ouvrir le menu"). La cause est la meme dans les deux composants :
>   un litteral gabarit qui code en dur `` ` : ` `` pour les deux langues.
>   `Francais` est en outre mal orthographie, sans cedille, dans un depot qui
>   accentue partout ailleurs ("Legal", "Cote d'Ivoire", "Ouvrir"). La checklist
>   de parite nomme explicitement les libelles ARIA parmi les surfaces ou une
>   chaine ne doit pas fuir d'une langue a l'autre. Defaut pre-existant, non
>   touche par cette PR, non arbitre a ce jour (aucune ligne D, aucun constat
>   anterieur), donc bloquant a la barre maximale. -> Porter le separateur dans
>   les dictionnaires (`fr.ts` avec l'espace insecable, `en.ts` sans espace)
>   plutot que dans le gabarit, et corriger `Francais` en `Français`.

**Two departures from the suggested shape**, both argued in D124: the separator
lives in `src/i18n/config.ts` rather than in the dictionaries, and the French
side keeps a plain space rather than gaining a non-breaking one.

## Acceptance criteria

1. No `aria-label` on any `/en/` page carries French typographic spacing,
   verified on the **built HTML**, not on the source.
2. The separator is **one piece of locale data read by both components**. No
   component hardcodes it and no component branches on the locale to pick it.
3. The French rendering does not move, byte for byte.
4. `npm run build` and `npm run check` are green, and the five acceptance
   criteria `FORM-FIX-001` delivered still hold.

## What was found before the fix

The exhaustive search, cited so a later round does not have to repeat it. Four
passes over `src/`, `functions/` and `server/`:

| Pass | What it looked for |
|---|---|
| A | every interpolated template literal |
| B | French spacing inside `en.ts` |
| C | French spacing inside any `aria-label` |
| D | any literal ` : ` string |

**Exactly two occurrences**, both already named by the review: `Header.astro:60`
and `LangSwitcher.astro:25`. `en.ts` is clean.

What the search surfaced and **deliberately left alone**, so the next reader
does not mistake silence for an oversight:

- `Header.astro:36`, `Footer.astro:42`, `AboutContent.astro:61` and
  `HomeContent.astro:28` join their parts with a **comma and a space**, which is
  correct in both languages. Not a defect.
- `server/notify-resend.ts:73-78,128,153` and
  `functions/api/contact.ts:214,237` do use ` : `, but they compose the
  **French-only notification email** and the **French-only console logs**, both
  correct under the repository language rule. `notify-resend.ts` is also being
  rewritten concurrently by `SITE-FIX-011` under D118, a second reason not to
  touch it.

## What changed

| File | Change |
|---|---|
| `src/i18n/config.ts` | `LABEL_SEPARATOR: Record<Locale, string>` added beside `LOCALE_LABEL`; `LOCALE_LABEL.fr` corrected from `Francais` to `Français` |
| `src/components/Header.astro` | value import of `LABEL_SEPARATOR`; line 60 reads it, indexed by `locale` |
| `src/components/LangSwitcher.astro` | same, plus a comment on the two languages that cross in this one label |

**The trap in `LangSwitcher`, recorded because it is not obvious.** Two languages
meet in that label and they do not index the same way. The label is a sentence of
the page, so its punctuation follows `locale`; only the **name** of the target
language follows `target`. An English page therefore reads
`Change language: Français`. Indexing the separator on `target` would reintroduce
the defect inverted, and the component now says so in place.
