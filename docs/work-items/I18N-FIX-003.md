**The one-line summary, after two rounds of getting it wrong.** Five call sites
composed a label with a hardcoded ` : `, so **all thirteen English pages
announced French colon spacing**. The separator is now locale data in
`config.ts`. The French side was correct throughout and does not move.

**What the title used to say, and why it changed twice.** It first named the
defect as living in three `aria-label`s. Round 1 found a fourth site in visible
text. Round 1's own fix then introduced a claim of a French defect that round 2
measured out of existence, while finding twelve real English occurrences the
first two methods had both passed. **The defect never ran in both directions;
the verification did.**

## Acceptance criteria

**Revised twice.** Round 1 widened criterion 1 beyond `aria-label`s. Round 2
rewrote how criteria 1 and 3 are **verified**, which is the change that mattered:
a criterion checked against the built HTML passed code that was still wrong.

1. **No string a user reads or hears**, visible text or announced name alike,
   carries the typographic convention of the other language. Verified by
   **measuring the accessible names Chrome computes** on the served site, in both
   languages, and by the built HTML for visible text only.
2. The separator is **one piece of locale data read by every component that
   composes a label**. No component hardcodes it and none branches on the locale
   to pick it.
3. **The announced and visible strings change only where they were wrong**, and
   nowhere else. Established by measuring the same pages against a
   `refonte-multipages` build, not by inference.
4. `npm run build` and `npm run check` are green, and the five acceptance
   criteria `FORM-FIX-001` delivered still hold.

## What was found, and how two verification methods were wrong before the third

**This section has been wrong twice and each review round demolished the method
the previous one had installed.** It is kept as a record of that rather than
rewritten clean, because the method is the whole subject of this item and its
failures are more instructive than its conclusion.

| Attempt | Method | What it missed | Found by |
|---|---|---|---|
| 1 | four greps over `src/` | `LegalPage.astro`, bare markup text between two interpolations. Claimed "exactly two occurrences" | review round 1 |
| 2 | sweep of the **built HTML** of the 26 pages | the twelve English card links, whose **announced** name is not their markup. Claimed "five occurrences", of which two never existed | review round 2 |
| 3 | **computed accessible names** via `Accessibility.getFullAXTree` over the served site, both languages | nothing known. It is the check that found attempt 2's error and the one that now backs the item | current |

**Why a source grep cannot work.** The occurrences share no syntactic form: a
template literal in one place, bare markup text in another, the first character
of a span in a third. Nothing matches them all.

**Why the built HTML cannot work either, and this is the subtler half.** An
accessible name computed from descendants **is not the element's text**. Chrome
inserts a space at an inline element boundary whenever the accumulated text does
not already end in one. Astro really does strip the source whitespace, so
`dist/en/index.html` reads `>Learn more<span class="visually-hidden">: Papillon...`
and every inspection of the markup passed it; the browser then announced
`Learn more : Papillon HR Suite`. A separator at the head of a sibling span can
**never** produce `Learn more: X`. See D133.

**The trap in `LangSwitcher`, recorded because it is not obvious.** Two languages
meet in that label and they do not index the same way. The sentence is a sentence
of the page, so its punctuation follows `locale`; only the **name** of the target
language follows `target`. An English page therefore reads
`Change language: Français`. Indexing the separator on `target` would reintroduce
the defect inverted, and the component now says so in place.

**Why that label is no longer an `aria-label` at all.** An `aria-label` is a flat
string, so nothing in it can be marked as belonging to a different language. The
anchor compensated by carrying `lang` set to the **target** language, which
declared the entire label to be in the other language and had a screen reader
announce `Change language` with French phonemes. `lang` describes this element's
own content, attribute text included; `hreflang` describes the document the link
points to. Only `lang` was wrong. The name now comes from two visually hidden
spans, and `lang` tags the language name alone. See D128.

**The two sweeps that back the item, and why it takes two.**

1. **Computed accessible names**, the authority for anything announced rather
   than read. A CDP probe drives `Accessibility.getFullAXTree` against the
   served site over **all 26 routes**, in both languages, and reports every
   named node whose name contains a colon, whatever its role, not links and
   buttons alone.

   **The measurement is a comparison, not a reading.** `refonte-multipages` is
   built and served on a second port and measured by the same probe, so every
   claim below is a delta between two runs. Result: **24 link names change, and
   nothing else does.** The twelve English card links lose both the space and
   the arrow, `Learn more : Papillon HR Suite →` becoming
   `Learn more: Papillon HR Suite`; the twelve French ones lose only the arrow,
   their colon spacing being identical on both sides. **Zero typographic defects
   remain on either side.**

   **The probe needed a guard, and finding that out is part of the record.** Its
   first version slept 600 ms after each navigation and silently produced
   nothing for `/produits` on the base build, which surfaced as an eleven-link
   phantom delta. A probe that reads nothing reports no defect, which is the
   same failure `bin/contrast_sweep` was given a guard for in D060 and that
   `bin/review_shots` shipped with until `SITE-FIX-009`. It now aborts with a
   non-zero exit when a page yields fewer than five named nodes, and both runs
   above are confirmed to cover 26 pages each.

   **WCAG 2.5.3, Label in Name, checked because the fix introduces `aria-label`
   on a link that has visible text.** Restricted to interface components,
   `a[href]`, `button` and `input`, with whitespace normalised: zero violations.
   The visible `Learn more` is contained in the announced
   `Learn more: Papillon HR Suite`, so the flat label does not orphan voice
   control.
2. **Built HTML**, the authority for **visible text** and for that alone. It is
   what confirms `Last updated: 30 July 2026` on the two English legal pages and
   `Dernière mise à jour : 30 juillet 2026` unchanged on the French ones.

**The decorative arrow left the accessible names as a side effect.**
`.link-arrow::after { content: ' \2192'; }` was injecting `→` into the announced
name of every card link in both languages, generated content being part of the
name computation. A flat `aria-label` excludes it. Measured: zero announced names
contain the arrow, while the arrow is still **visible** on the page, confirmed by
capture at 1440 px. `.link-arrow` is used by these two components only, so no
other name was affected.

**Criterion 3, verified by measurement.** The announced names change on exactly
the surfaces that were wrong, all of them English: the header disclosures and the
switcher on 13 pages, the twelve card links on 3 pages, and the `Last updated`
line on 2 pages. **Every French announced name is unchanged**, which is the
measured version of what round 1 asserted and got wrong.

**A visual pass was run, and it was due.** The first version of this fiche argued
that no visual pass was needed because no CSS had changed. That inference no
longer holds: D128 changes the DOM of the language switcher, which sits in the
header of every page. `npm run preview` on **port 4325**, ownership confirmed
with `lsof -p <pid> -d cwd` before any capture, then 24 captures via
`bin/review_shots` at 360, 768 and 1440 px over `/`, `/en`, `/produits`,
`/en/products`, `/services`, `/en/services`, `/mentions-legales` and
`/en/legal-notice`. No layout movement: `.visually-hidden` is `position:
absolute`, so the two added spans are out of flow. `Last updated: 30 July 2026`
read in the browser on `/en/legal-notice`. **The phrasing is corrected as the
review asked**: the right claim is "no visual delta expected", never "no visual
pass needed".

**`FORM-FIX-001` not regressed**, checked on the built output: Turnstile still
carries `data-language="en"` on `/en/contact` and `fr` on `/contact`; both state
panels keep `tabindex="-1"` and the error panel its `role="alert"`; the
double-submission guard and its `pageshow` re-arm are still present; the form
