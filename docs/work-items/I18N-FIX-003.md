## Acceptance criteria

directions, so an English-only criterion and a byte-identical French one were

1. **No rendered string on any page**, visible text or accessible name alike,
   carries the typographic convention of the other language. Verified on the

2. The separator is **one piece of locale data read by every component that

   nowhere else.
4. `npm run build` and `npm run check` are green, and the five acceptance
   criteria `FORM-FIX-001` delivered still hold.

## What was found, and how the first search got it wrong

**The first version of this section claimed a four-pass source search was
exhaustive and that the pattern had exactly two occurrences. Both claims were
false**, and review round 1 blocked the item on it. The passes were:

| Pass | What it looked for | Why it was not enough |
|---|---|---|
| A | every interpolated template literal | `LegalPage.astro:39` is bare markup text between two interpolations |
| B | French spacing inside `en.ts` | correct, `en.ts` is clean, but the defect was never in the dictionaries |
| C | French spacing inside any `aria-label` | two of the five occurrences are not `aria-label`s at all |
| D | any literal ` : ` string | matched neither the bare markup text nor a separator written as the leading character of a span |

**The lesson, and it is the reason this section is kept rather than quietly
rewritten**: the five occurrences share no syntactic form. One is a template
literal, one is markup text between two interpolations, one is the first
character of a visually hidden span. **They share only what they render**, so a
grep over the source cannot enumerate them and the built output is the only
authority. The sweep that now backs this item runs over `dist/`, in both
languages, and flags any colon whose spacing does not match the page's language.

| File | Change |

**The trap in `LangSwitcher`, recorded because it is not obvious.** Two languages
meet in that label and they do not index the same way. The sentence is a sentence
of the page, so its punctuation follows `locale`; only the **name** of the target
language follows `target`. An English page therefore reads
`Change language: Français`. Indexing the separator on `target` would reintroduce
the defect inverted, and the component now says so in place.

**Why that label is no longer an `aria-label` at all.** An `aria-label` is a flat
string, so nothing in it can be marked as belonging to a different language. The
anchor compensated by carrying `lang` set to the **target** language, which
declared the entire label to be in the other language and had a screen reader
announce `Change language` with French phonemes. `lang` describes this element's
own content, attribute text included; `hreflang` describes the document the link
points to. Only `lang` was wrong. The name now comes from two visually hidden
spans, and `lang` tags the language name alone. See D128.
